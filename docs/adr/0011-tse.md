# ADR-0011: Target Speaker Extraction (TSE) — Séparation N speakers

## Statut

Accepté

## Context

Après ADR-0010, le plafond de l'architecture actuelle est atteint sur données synthétiques :

- DER 0,091, pairwise-F1 0,651, ARI 0,480 (4 speakers, seeds 1–4, configuration optimale window 1,0 s / hop 0,33 s / cell 0,125 s)
- WER non-overlap 0,607, WER overlap 0,807 (benchmark 4 speakers, baseline OFF)
- SepFormer limité à 2 stems dégrade le WER overlap (0,807 vs 0,768 OFF, ADR-0008, 4 locuteurs réels) — deux tiges contenant chacune ~2 locuteurs rendent l'assignation par similarité et la transcription par tige non fiables (N4)
- La séparation conditionnelle OFF reste le comportement par défaut (ADR-0008 renforcé)

Le TSE (Target Speaker Extraction) est une alternative légère, conditionnée par locuteur : modèle STFT-domain FiLM ~1.2M paramètres (1 237 122 avec `channels=128`, `n_blocks=3`, `n_fft=512`, `hop=256`, fenêtre hann), conditionné sur embeddings ECAPA 192-d (speechbrain/spkrec-ecapa-voxceleb, gelé). Il est entraînable sur les datasets synthétiques Piper existants (`data/synthetic/train_3000_*`, cache TTS `models/piper/samples/`) sans dépendance externe gated ou cloud, et produit N stems sans limite théorique — limite pratique : nombre de voix Piper disponibles (6).

Mesure de référence : `uv run python -c "from conversation_deconvolution.tse.model import TseModel; print(sum(p.numel() for p in TseModel().parameters()))"` → `1237122` (`channels=128`). Variante `channels=64` (défaut `TseConfig`) → `323650` params.

## Decision

Implémenter un séparateur TSE léger en interne, entraîné sur données synthétiques déterministes, derrière le backend `separation.backend: tse`. Le comportement par défaut reste **OFF** (`separation.enabled: false`, ADR-0008/0011 renforcés). Le TSE est activable via :

- CLI : `--separation-backend tse` (sur `run` et `benchmark`, implique `enabled: true` sauf `passthrough`)
- Config YAML : `separation.backend: tse`
- Entraînement : `deconvolute train-tse --epochs 30 --out models/tse/model.pt` (datasets `train_3000_*` existants, SNR bande-limitée [10,20] dB, checkpoints `models/tse/model.pt` + `models/tse/hparams.yaml`)

Architecture retenue : `TseModel` (STFT `n_fft=512` `hop=256`, encodeur conv2d, 3 blocs FiLM résiduels, décodeur → masque sigmoïde complexe, loss SI-SDR waveform), `TseDataset` en ligne (mix = somme timeline + bruit band-limité, cible = signal locuteur isolé, embedding référence exclusif non utilisé dans le mix), `TseSeparator.separate(mix, regions, speaker_refs=None)` où `speaker_refs = {label: centroid}` construit depuis `diarizer.speaker_centroids_` (ordre trié des clés → N stems, métadonnée `num_speakers`).

## Alternatives considered

- **SepFormer avec fine-tuning >2 stems** : nécessite un modèle public >2 stems, non disponible ; le modèle whamr16k actuel est figé à 2 stems (ADR-0008/N4).
- **Modèle externe (OpenUnmix, Demucs, SepFormer large)** : dépendance lourde (poids, runtime), pas local-first, non aligné avec la doctrine DIY du projet.
- **GNN sur features audio ou embeddings frame-level** : coût élevé, peu de signaux discriminants en amont (similarité sémantique déjà faible, cosinus anti-corrélé à l'éval — ADR-0009), goulot situé sur la pureté des tours / fusion de voix, pas sur le modèle de regroupement.
- **Ne rien faire (rester OFF sans backend TSE)** : rejeté, l'infrastructure TSE est légère (~1.2M params), entraînable localement et débloque la séparation N speakers sans dépendance externe.

## Consequences

### Positive

- Séparation **N speakers sans limite théorique** (limite : voix Piper = 6).
- **~1.2M params** (variante 323 k avec `channels=64`), entraînement local, pas de dépendance externe, compatible pipeline existant via `build_pipeline` et `--separation-backend`.
- Réutilise les datasets `train_3000_*` existants, cache TTS déterministe, bruit band-limité paramétrable (`tse.noise_bandwidth`, `snr_low/high`).
- Métadonnée `num_speakers` exposée dans `SeparationResult.meta` et rapport benchmark.

### Negative

- Deux chemins de pipeline à maintenir (OFF par défaut, TSE derrière flag).
- Entraînement nécessaire (GPU, ~2–3h pour 8 datasets, 30 epochs) avant utilisation ; modèle non pré-entraîné livré.
- Critère d'acceptation non encore validé : **WER overlap(TSE) < WER overlap(OFF) (0,807)** sur benchmark 4 speakers — en attente Task 8.
- Deux variantes de capacité (`channels=64` vs `128`) à documenter ; le défaut config (64) diffère du défaut modèle (128).

## Reconsideration criteria

Activer par défaut si **WER overlap(TSE) < WER overlap(OFF)** sur le benchmark 4 speakers (seeds 1234+, `deconvolute benchmark --separate --separation-backend tse`). Si le critère est atteint, envisager `separation.enabled: true` + `backend: tse` par défaut et mise à jour de `configs/default.yaml`. Sinon, maintenir OFF (ADR-0008/0011) et itérer sur hyperparams ou architecture (ex. Lite-TFNet).
